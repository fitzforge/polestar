## Why "fit first"

In November 2026 contributors were asked for round after round of
technical changes on features whose fit had never been decided, and some
were turned down without the maintainer's own word on them. That spends
people's time and leads them on. So the rules now start with us: what
Polestar is is written down, every feature gets a yes, no or later from the
maintainer within three days before anyone reviews its code, a later names
its release, ideas are talked through in an issue before they are built,
and only the maintainer declines someone's work (CONTRIBUTING.md, "Before
you build a feature"). The testing side of the same month is in
[0.4.2-lessons.md](0.4.2-lessons.md).
